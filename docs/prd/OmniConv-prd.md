# 💡 OmniConvert 产品需求文档 (PRD) v2.0

## 1. 产品背景与市场痛点

### 为什么我们需要 OmniConvert？

在日常工作中，我们总免不了要和各类文件打交道，但从个人到企业，都面临着一堆麻烦：

*   **成本高昂**：市面上功能全面的转换工具，如 CloudConvert 或 Zamzar，要么限制免费使用次数，要么对文件大小设限，想用好就得付费。
*   **隐私泄露风险**：把包含个人隐私或商业机密的文件上传到云端服务器，存在数据泄露的巨大风险。
*   **恶意软件威胁**：一些免费的在线转换网站会悄悄植入恶意软件，窃取个人信息，甚至将用户的敏感文件在互联网上公开。
*   **工具碎片化**：图片、视频、文档需要不同的软件来处理，切换来去很麻烦。
*   **体验妥协**：免费工具常常塞满广告，限制多多。

一个理想的工具，应该是**免费、安全、全能、体验好**的。

## 2. 产品概述

**OmniConvert** 就是这样一个“全能文件转换器”。

它是一个开源项目，核心价值在于**所有转换都在你本地完成，文件不用离开你的设备**。目标用户是所有对文件转换有需求，并且看重隐私和效率的人。

## 3. 功能需求

### 3.1 核心转换引擎

产品基于以下六大开源引擎构建，覆盖日常所需的各类文件格式：

| 引擎 | 支持类型 | 核心支持格式 |
| :--- | :--- | :--- |
| **ImageMagick** | 图片 | JPG, PNG, GIF, WebP, SVG, HEIC, TIFF, BMP, ICO |
| **FFmpeg** | 音视频 | 音频: MP3/AAC/FLAC/WAV/OGG<br>视频: MP4/AVI/MKV/MOV/WebM |
| **Pandoc** | 文档/标记语言 | MD ↔ DOCX ↔ HTML ↔ PDF ↔ EPUB ↔ LaTeX |

### 3.2 功能详情

*   **全平台覆盖**：核心是一次编写，同时构建出 Web 应用和 Windows/macOS/Linux 桌面客户端。提供 Web 版和可下载的离线桌面版。
*   **零上传，绝对安全**：**Web版和桌面版的核心逻辑统一**。Web 版通过 WASM 技术在浏览器里直接转换；桌面版则内置转换引擎，做到完全本地处理。
*   **智能格式检测与推荐**：上传文件后，自动识别格式，并为你推荐最适合的目标格式。
*   **丰富的转换选项**：每个引擎都提供可展开的“高级选项”，方便进行更精细的控制。
*   **批量处理与打包**：支持多文件批量转换，完成后可以打包成 ZIP 下载。
*   **结果即时预览**：转换完成后，支持图片、音频、视频的直接预览。
*   **转换历史记录**：转换记录会安全地保存在本地，方便随时查看。
*   **深色/浅色主题切换**：跟随系统或手动设置，让眼睛更舒服。
*   **响应式设计**：在各种屏幕大小的设备上都能获得良好的使用体验。
*   **多语言支持**：支持简体中文、繁体中文、英语、法语、德语、西班牙语、俄罗斯语、日语、韩语、意大利、葡萄牙。

## 4. 技术架构

项目采用“一次编码，多端构建”的技术方案：

| 层面 | 技术栈 | 选择理由 |
| :--- | :--- | :--- |
| **前端框架** | Nuxt 3 (Vue 3 + TypeScript) | Vue 全栈框架，路由、SSG/SSR、API Routes 开箱即用 |
| **样式/UI组件** | Tailwind CSS + shadcn-vue | 开发效率高，风格现代|
| **状态管理** | Pinia | Vue 官方推荐，API 简洁，类型支持强 |
| **跨平台框架** | Tauri 2.0 | 打包体积小，性能好，前端与 Vue 完美集成 |
| **文件拖拽/上传** | 浏览器原生 Drag & Drop API 封装，或 `vue-file-dropzone` | 轻量、灵活，避免过度依赖 |
| **核心引擎 (浏览器端)** | `@ffmpeg/ffmpeg`, `magick-wasm`, `pandoc` | WASM 库，与框架无关 |
| **核心引擎 (桌面端)** | 原生 CLI 工具包 | 嵌入 Tauri Rust 后端，通过 Sidecar 调用 |
| **部署平台** | Vercel (Web), GitHub Releases (桌面端) | 分别部署静态/SSG 站点和分发客户端 |

### 4.1 转换方案的选择逻辑

为了平衡隐私安全与处理性能，项目采用两种不同的转换方案：

*   **浏览器端 (WebAssembly) 转换**：
    *   **适用场景**：Web 在线版。
    *   **技术原理**：利用 `@ffmpeg/ffmpeg` 和 `magick-wasm` 等库，将 C/C++ 代码编译为 WebAssembly，直接在浏览器中运行。
    *   **优势**：实现零上传，最大程度保障用户隐私。
    *   **局限性**：受浏览器内存限制，处理超大文件（如>1GB视频）时可能性能不足，此时可提示用户使用桌面客户端。

*   **桌面端 (原生 CLI) 转换**：
    *   **适用场景**：Windows/macOS/Linux 桌面客户端。
    *   **技术原理**：将 FFmpeg、Pandoc 等原生 CLI 工具与 Tauri 应用打包在一起，通过 Rust 后端进行调用。
    *   **优势**：拥有原生性能，能稳定处理超大文件，无浏览器内存限制。

*   **智能选择逻辑**：
    1.  **默认优先**：在 Web 版中，默认使用 WASM 方案。
    2.  **性能提示**：当检测到文件过大（例如 >500MB）时，界面会提示建议使用桌面客户端。
    3.  **桌面端优先**：桌面客户端永远优先使用内置的原生 CLI 工具，保证最佳性能。

### 4.2 客户端打包方案

*   **Tauri 配置**：在 `tauri.conf.json` 中使用 `externalBin` 属性，指向对应的 CLI 工具二进制文件。
*   **跨平台打包**：
    *   **Windows**: 打包为 `.exe` 或 `.msi` 安装程序。
    *   **macOS**: 打包为 `.dmg` 镜像文件。
    *   **Linux**: 打包为 `.deb` 软件包或 `.AppImage` 可执行文件。

## 5. 与竞品的差异化亮点

OmniConvert 不只是“又一个转换工具”，它解决了其他工具没能完美解决的问题：

*   **vs. 在线转换网站 (如 CloudConvert, Zamzar)**：免费、无限制、无需上传文件，隐私绝对安全，没有任何隐形收费或恶意软件风险。
*   **vs. 其他本地开源工具 (如 FileConverter, VERT)**：功能更全能（集成六大引擎），交互更现代，最重要的是**提供真正的全平台覆盖（Web + 桌面客户端）**，打破平台限制。

## 6. 用户体验流程

1.  **打开应用**：用户打开 OmniConvert 的 Web 版或桌面客户端，看到统一的首页。
2.  **上传文件**：通过拖拽或点击，上传一个或多个文件。
3.  **智能识别**：系统自动识别并显示文件的当前格式。
4.  **选择输出**：系统推荐常用的目标格式，用户也可以手动选择。
5.  **开始转换**：用户点击按钮开始转换，界面显示进度条。
6.  **获取结果**：转换完成后，用户可以直接预览或下载文件。
