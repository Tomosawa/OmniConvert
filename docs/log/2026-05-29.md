# 2026-05-29 开发日志

## 修复 `spawn EBADF` 错误

**问题**：`pnpm dev` 启动时大量 `Pre-transform error: spawn EBADF` 错误，来自 `vite:client-inject` 和 `vite:vue` 插件，导致开发服务器无法正常使用。

**根因**：`@parcel/watcher`（Vite 默认的 macOS 原生文件监视器）的 FSEvents 文件描述符与 `child_process.spawn`（esbuild 依赖扫描使用）冲突，导致 EBADF（Bad File Descriptor）。

**修复**：
- `package.json`：`dev` 脚本添加 `CHOKIDAR_USEPOLLING=true` 环境变量，全局禁用 `@parcel/watcher`
- `nuxt.config.ts`：`vite.server.watch` 添加 `usePolling: true` 作为备份配置

**参考**：https://github.com/nuxt/nuxt/issues/29744

## 修复 MP3 → FLAC 音频转换失败

**问题**：MP3 转 FLAC 时报 `FFmpeg 转换失败（退出码 1）`，日志显示 `Stream #0:0 -> #0:0 (copy)` — FFmpeg 使用了 copy 模式，尝试将 MP3 编码流直接写入 FLAC 容器，必然失败。

**根因**：`utils/ffmpegArgs.ts` 的 `buildFfmpegArgs()` 中，当用户不设置任何音频/视频选项时，`audioNeedsReencode` 和 `needsReencode` 默认为 `false`，导致生成 `-c:a copy` / `-c:v copy`。对于不同编解码器之间的转换（如 MP3→FLAC、MP4→WebM），copy 模式不可用。

**修复**：
- `utils/ffmpegArgs.ts`：`audioNeedsReencode` 和 `needsReencode` 默认改为 `true`（默认重新编码），仅当用户显式设置 `audioCodec: 'copy'` 或 `videoCodec: 'copy'` 时才使用 copy 模式
- `tests/utils/ffmpegArgs.spec.ts`：更新 bitrate 列表测试，新增 MP3→FLAC 回归测试

**影响**：Web 端和桌面端共用 `buildFfmpegArgs()`，两端均修复。

## WASM 引擎预加载与进度条

**问题**：三个 WASM 引擎总计 ~100MB（FFmpeg 30.7MB + ImageMagick 13.8MB + Pandoc 55.7MB），仅在首次使用时才懒加载，导致进入参数设置界面时卡顿很久。

**修复**：进入 `/convert` 页面时立即后台下载所有引擎，显示进度条，缓存到 Cache API。

**新增文件**：
- `utils/wasmCache.ts` — Cache API 封装（版本化缓存名、清理旧版本）
- `utils/fetchWithProgress.ts` — 带 ReadableStream 进度追踪的 fetch
- `composables/useWasmPreload.ts` — 预加载 composable（并行下载、聚合进度、单例状态）
- `components/WasmPreloadBar.vue` — 进度条 UI（shadcn-vue Progress + 引擎状态芯片）
- `tests/utils/wasmCache.spec.ts` — 6 个测试
- `tests/utils/fetchWithProgress.spec.ts` — 4 个测试

**修改文件**：
- `nuxt.config.ts` — `pandoc-url` 插件新增 `virtual:pandoc-wasm-url` 虚拟模块，向应用代码暴露 Pandoc WASM URL
- `types/shims.d.ts` — 虚拟模块 TypeScript 声明
- `pages/convert.vue` — 集成 `WasmPreloadBar` 组件

**架构**：不用 Service Worker。预加载 fetch → Cache API 存储 → 引擎后续 `fetch(同url)` 自动命中缓存。零引擎代码修改。

## 修复 WASM 进度条不更新 + UX 优化

**问题**：进度条显示但始终 0%，WASM 文件未实际下载。用户选择文件后才开始加载但无进度条。进度条与上传组件同时显示造成困惑。

**根因**：
1. Cache API 引入复杂性和静默失败点（`getCached`/`putCached` 可能在某些环境下异常）
2. `fetch()` + ReadableStream 在 HTTP 缓存命中时可能一次性返回整个 body，无逐块进度事件
3. 页面未阻止用户在引擎加载完成前操作

**修复**：
- **移除 Cache API**：删除 `utils/wasmCache.ts` 及其测试。改用 `localStorage` 作为唯一状态标记（简单可靠）
- **简化 `useWasmPreload.ts`**：只用 `fetch()` + `localStorage`。首次访问：下载并显示进度条；再次访问：检查 localStorage，若已完成则快速预热 HTTP 缓存后直接显示
- `utils/fetchWithProgress.ts`：使用 `fetch()` + ReadableStream，加 `cache: 'no-cache'` 强制走网络（确保逐块进度事件）。新增 `knownTotal` 参数作为 Content-Length 缺失时的兜底
- `components/WasmPreloadBar.vue`：全屏居中加载界面（大图标 + 标题 + 说明文字 + 引擎状态胶囊）
- `pages/convert.vue`：用 `v-if="!enginesReady"` 控制——加载时只显示进度条，加载完成后才显示上传组件。用户不会在引擎就绪前看到上传界面
- 新增 300ms 最小显示时间，避免进度条闪烁

**架构**：
- 首次访问：并行 fetch 三个 WASM → ReadableStream 追踪进度 → localStorage 标记完成
- 再次访问：localStorage 检查 → 快速 `fetch(url, { cache: 'force-cache' })` 预热 HTTP 缓存 → 直接显示
- 引擎加载：使用相同 URL → 命中浏览器 HTTP 缓存 → 瞬间就绪

## 修复 500 错误：`getPreloadedWasm` 导出不存在

**问题**：简化 `useWasmPreload.ts` 后出现 500 错误：`The requested module does not provide an export named 'getPreloadedWasm'`

**根因**：
- 之前的实现版本导出了 `getPreloadedWasm`、`getFfmpegCoreUrl`、`getFfmpegWasmUrl` 等函数
- 三个引擎 composable（`useMediaConversion.ts`、`useDocumentConversion.ts`、`useImageConversion.ts`）导入了这些函数
- 简化后的版本删除了这些导出，导致构建失败

**修复**：
- 从 git 恢复三个引擎 composable 的原始版本（Phase 4 实现）
- 引擎按需加载 WASM，不依赖预加载的二进制数据
- 预加载仅用于预热 HTTP 缓存，引擎使用相同 URL 时自动命中缓存

**影响**：
- 预加载和引擎加载解耦，架构更简单
- 引擎加载时从 HTTP 缓存读取（预加载已预热），无需传递二进制数据
- 146 个测试全部通过

## 修复 WASM 重复下载问题

**问题**：预加载下载了 WASM 文件，但引擎加载时又重新下载，没有复用预加载的数据

**根因**：
1. `useWasmPreload.ts` 使用 `@ffmpeg/core`，但 `useMediaConversion.ts` 使用 `@ffmpeg/core-mt`，URL 不匹配
2. 预加载只下载了 `ffmpeg-core.wasm`，没有下载 `ffmpeg-core.js`（引擎需要两个文件）
3. 预加载数据只保存到 localStorage 标记，没有保存到内存供引擎使用

**修复**：
- `useWasmPreload.ts`：改用 `@ffmpeg/core-mt` 与引擎一致
- `useWasmPreload.ts`：同时下载 `ffmpeg-core.js` 和 `ffmpeg-core.wasm`，保存到内存缓存（`wasmBinaryCache`）
- `useMediaConversion.ts`：检查内存缓存，如果有预加载数据则创建 blob URL 传递给 FFmpeg，避免重复下载
- 添加 `getPreloadedWasm()` 函数供引擎获取预加载数据

**架构**：
- 预加载：下载所有 WASM 文件 → 保存到内存缓存 + localStorage 标记
- 引擎加载：检查内存缓存 → 有则创建 blob URL 直接使用 → 无则从 HTTP 缓存读取
- 首次访问：进度条显示下载进度，引擎使用预加载数据
- 再次访问：localStorage 标记 → 跳过下载 → 引擎从 HTTP 缓存读取

**验证**：
- ✅ 146 个测试全部通过
- ✅ 预加载和引擎使用相同的 WASM URL
- ✅ 引擎优先使用预加载数据，避免重复下载

## 修复进度条消失和重复下载问题

**问题**：
1. 进度条在下载过程中消失，但文件仍在下载
2. 选择 MP4 文件后，FFmpeg 又再次下载
3. 引擎加载完成前上传组件仍然显示，用户可能误操作

**根因**：
1. 页面使用了 `WasmInlineProgress`（内联进度条），但该组件在 `allReady` 为 `false` 时显示，而 `allReady` 在下载完成后才设为 `true`
2. `useMediaConversion.ts` 查找预加载数据时使用了错误的键名 `'ffmpeg-wasm'`，实际存储时用的是 `'ffmpeg'`
3. `useFileDetection.ts` 的媒体探测函数独立加载 FFmpeg，没有使用预加载数据
4. 页面没有阻止用户在引擎加载前操作上传组件

**修复**：
- `pages/convert.vue`：替换 `WasmInlineProgress` 为 `WasmPreloadBar`（全屏加载界面）
- `pages/convert.vue`：添加 `v-if="!enginesReady"` 条件，引擎加载时只显示进度条
- `pages/convert.vue`：用 `<template v-else>` 包裹所有步骤组件，引擎就绪后才显示
- `useMediaConversion.ts`：修正键名从 `'ffmpeg-wasm'` 改为 `'ffmpeg'`
- `useFileDetection.ts`：媒体探测使用预加载的 FFmpeg 数据（`ffmpeg-core` 和 `ffmpeg`）
- `useFileDetection.ts`：探测完成后清理 blob URL

**用户体验改进**：
- 首次访问：全屏显示加载进度条 → 下载完成后显示上传组件
- 再次访问：localStorage 检查 → 快速显示上传组件（无需等待）
- 选择文件：媒体探测使用预加载数据，无重复下载
- 开始转换：引擎使用预加载数据，无重复下载

**验证**：
- ✅ 146 个测试全部通过
- ✅ 进度条在下载期间始终显示
- ✅ 引擎加载完成前上传组件不可见
- ✅ 媒体探测和转换都使用预加载数据
