## 修复 H.265 编码卡死（进度停在 5%）

- **根因**：libx265 默认尝试创建内部线程池，在 WASM 单线程环境中挂起
- **修复**：
  - `-threads 1` 强制 FFmpeg 使用单线程（阻止 libx265 尝试创建系统线程）
  - `-x265-params frame-threads=1` 限制 x265 内部帧线程数为 1
  - `-pix_fmt yuv420p` 补全之前缺失的像素格式（libx264/libvpx-vp9 已有，libx265 缺失）
  - `-x265-params log-level=warning` 减少冗余日志
  - 编码超时从 5min 提升至 10min（x265 WASM 编码本身较慢）
  - 新增 FFmpeg 日志监听：检测到 `frame=`/`size=`/`time=` 输出时进度从 5% 跳至 8%，让用户感知到编码已开始
- **放弃 `@ffmpeg/core-mt` 多线程方案**：其 `ffmpeg-core.worker.js` 使用 `import()` 语句，但被 `ffmpeg-core.js` 以经典 Worker（非 module）方式加载，在 Vite 下无法正常工作
- 新增 libx265 参数构建单元测试

**涉及文件**: `composables/useMediaConversion.ts`, `utils/ffmpegArgs.ts`, `tests/utils/ffmpegArgs.spec.ts`, `nuxt.config.ts`

## 添加编码器挂起看门狗

- **问题**：libx265 在 WASM 单线程环境下即使加了 `-threads 1` 和 `frame-threads=1`，仍可能完全无响应（45秒无任何日志输出），用户只能看到进度卡在 5% 无限等待
- **修复**：
  - 添加 45 秒看门狗定时器：`ff.exec()` 启动后开始计时，FFmpeg 每产生日志输出就重置计时器
  - 如果 45 秒内无任何 FFmpeg 输出 → 编码器已挂起 → 主动 `destroyFfmpeg()` 终止 WASM worker → 抛出用户友好错误提示
  - 错误提示明确建议改用 H.264 (libx264)，兼容性更好且速度更快
- **效果**：用户不再无限等待，45 秒内就能看到明确的错误原因和解决方案

**涉及文件**: `composables/useMediaConversion.ts`
