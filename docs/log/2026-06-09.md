# 2026-06-09 开发日志

## 桌面端修复与增强

### Bug 修复：引擎找不到输入文件
- 根因：`fs.writeFile` 未指定 `baseDir: BaseDirectory.Temp`，绝对路径解析不稳定
- 修复：所有 desktop composable 的 FS 操作改用 `BaseDirectory.Temp` + 相对文件名，sidecar CLI 参数仍使用绝对路径
- 涉及文件：`useDesktopImageConversion.ts`、`useDesktopMediaConversion.ts`、`useDesktopDocumentConversion.ts`
- 增加了写入验证（`fs.exists` 检查确保临时文件确实被创建）

### 增强：桌面端多线程 + H.265
- FFmpeg 桌面端添加 `-threads 0`（自动多核分配）
- H.265 桌面端使用 `x265-params: log-level=warning`（无单线程限制）
- H.265 Web 版保留 `x265-params: log-level=warning:frame-threads=1:wpp=0:pools=none`
- 侧车错误诊断增强：stderr 中的文件相关错误（No such file、cannot open、Permission denied）自动附加路径信息

### Bug 修复：桌面端启动空白页
- 根因：`tauri.conf.json` 缺少 `beforeDevCommand` 和 `devUrl` 配置，开发模式无法找到前端页面
- 修复：添加 `beforeDevCommand: "pnpm dev"` + `devUrl: "http://localhost:3000"`，简化 `tauri:dev` 脚本
- README 更新了完整的桌面端开发指南

### Bug 修复：桌面端显示 WASM 加载界面
- 根因：`useWasmPreload` 在桌面端 `preload()` 直接 return 但未设置 `allReady=true`
- 结果：`convert.vue` 的 `v-if="!enginesReady"` 永远为 true → 卡死在"正在加载转换引擎…"
- 修复：桌面端立即设置 `allReady=true`、`isEngineReady()`=true、`enginePercent()`=100

### 不影响 Web 版
- 所有改动仅涉及 desktop composable 和 `ffmpegArgs.ts` 的 desktop 分支
- Web 版 WASM 引擎逻辑完全不变
